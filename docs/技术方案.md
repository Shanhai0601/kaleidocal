# KaleidoCal 技术方案

## 1. 总体架构

```
             ┌────────────┐
  公历/儒略历 │  julian.py │  ◄── 儒略日（JD）核心
             └─────┬──────┘
                   │  JD（中间货币）
   ┌───────────┬────┼───────────┬───────────┬────────────┐
   │  astro.py │ ganzhi.py │ chinese.py │  maya.py   │ republican.py │
   │ 太阳/朔   │  干支生肖 │   农历     │  玛雅历   │  法国共和历  │
   └───────────┴───────────┴───────────┴───────────┴────────────┘
                   │
             ┌─────┴──────┐
             │   cli.py   │  ◄── 命令行入口 / 综合排盘
             └────────────┘
```

核心设计是**以儒略日（Julian Day，JD）作为所有历法的「中间货币」**。任何历法只需实现「本历法 ↔ JD」两个方向的转换，N 种历法之间即可任意互转（共 N 个转换器），而无需维护 N×(N-1) 个两两转换函数。

## 2. 儒略日（julian.py）

- **约定**：JD 的整数部分对应**正午 12:00**。因此 `JDN = int(JD)` 可直接用于干支纪日、星期等取模运算，无需额外偏移。
- **公历改革**：`GREGORIAN_REFORM_JD = 2299160.5`，即 1582-10-15 起用格里历（Gregorian），此前用儒略历（Julian）。`calendar` 参数支持 `auto`（默认，按改革日自动切换）/ `gregorian` / `julian`。
- **纪年约定**：天文纪年（公元前 1 年 = 0，公元前 2 年 = -1），便于连续运算。
- 算法采用 Meeus《Astronomical Algorithms》第 7 章的标准公式。

## 3. 天文算法（astro.py）

农历的「定气定朔」依赖两个天文量，均由纯算法实时计算：

### 3.1 太阳视黄经（定节气）

- `solar_apparent_longitude(jde)`：Meeus 低精度太阳理论，含光行差与章动简化修正，精度约 0.01°（时间误差 < 1 分钟）。
- `solar_term_jd(year, k)`：第 k 个节气（k = 0..23，对应黄经 15°×k）。在平均日期 ±18 天区间内二分求根（50 次迭代收敛到秒级），无数据表。

### 3.2 朔（定朔）

- `new_moon_jd(k)`：Meeus 第 49 章新月公式，含主周期项修正（行星项省略，误差 < 1 分钟）。
- 配合 `new_moon_before` / `new_moon_after` 做区间定位。

## 4. 干支与生肖（ganzhi.py）

- 纪年：公元 4 年为甲子年，`天干 = (year-4) % 10`，`地支 = (year-4) % 12`。
- 纪日：以儒略日为基准，`天干 = (JDN+9) % 10`，`地支 = (JDN+1) % 12`，六十甲子序号 `(JDN+49) % 60`。锚点 **2019-01-27 = 甲子日**（JDN 2458511）。
- 纪时：十二时辰（23–01 子时…）+ 五鼠遁时法（由日干推子时天干）。

## 5. 农历（chinese.py）

采用**定气定朔**法，完全由天文算法驱动：

1. **定月**：以「朔」为每月初一，大月 30 天、小月 29 天。
2. **定月名**：以「中气」（太阳视黄经 30° 整数倍）定月名，冬至所在月必为十一月。
3. **置闰**：若某月不含任何中气，则为闰月，闰它前一个月。
4. **定正月初一（春节）**：= **前一年**冬至后的第二个朔。

### 5.1 关键坑点：时区

朔与中气是天文学「时刻」（世界时 UT），但农历的月、日、闰月归属按**北京时间（UTC+8）的哪一天**判定。因此所有月边界与中气归属都先 `+8h` 换算成北京时间日期再做区间比较。

> 若不处理时区，朔落在世界时 20:00–24:00（即北京次日凌晨）时，会出现整月错位一天、闰月错移一位的错误（本项目开发中实际踩到，见 `chinese.py` 顶部注释）。

### 5.2 关键函数

- `lunar_new_year_jd(year)`：正月初一朔时刻（依据 `year-1` 年冬至）。
- `build_lunar_year(year)`：构建整年朔望月份表，逐月判定中气归属与闰月。
- `gregorian_to_lunar` / `lunar_year_info`：对外换算接口。

## 6. 玛雅历（maya.py）

三套并行历法 + 组合轮回：

- **长纪历**：`baktun.katun.tun.uinal.kin` 五位置计数。位权分别为 144000 / 7200 / 360 / 20 / 1 天（注意 uinal 是 18 进制：18 uinal = 1 tun，故 tun 位权是 18×20=360 天）。纪元 `0.0.0.0.0 = JDN 584283`（GMT 584283 关联常数），由此推出 `2012-12-21 = 13.0.0.0.0`。
- **卓尔金历（Tzolk'in）**：260 天（13 数字 × 20 日名）。纪元日相位 4 Ahau，经中国剩余定理解 `p≡3(mod13) 且 p≡19(mod20)` 得相位偏移 `_TZOLKIN_EPOCH_OFFSET = 159`。
- **哈布历（Haab）**：365 天（18 月 × 20 天 + 5 天 Wayeb）。纪元日 = 8 Cumku，加 348 天偏移对齐。
- **历法轮回（Calendar Round）**：Tzolk'in + Haab 组合，52 年循环。

## 7. 法国共和历（republican.py）

- 元年 An I = 1792-09-22（秋分）。
- 一年 12 月 × 30 天 + 年末补日（闰年 6 天，平年 5 天）。补日用 `month=13` 表示。
- 置闰采用 Romme 规则化闰年（与格里历闰年规则一致），葡月 1 日固定为 9-22。这是「规则化共和历」口径，适合换算玩具（历史上实际置闰与秋分有过出入，已在模块注释中说明）。

## 8. 测试策略（tests/）

每个模块独立测试，用**已知历表锚点对拍**而非自证：

| 模块 | 关键锚点 |
| --- | --- |
| julian | 2000-01-01 = JDN 2451545；随机 2000 组 round-trip |
| astro | 二十四节气单调性、间隔 13–17 天 |
| ganzhi | 2019-01-27 = 甲子日；纪年周期 |
| maya | 0.0.0.0.0 = 4 Ahau / 8 Cumku；2012-12-21 = 13.0.0.0.0 |
| republican | 1792-09-22 = An 1 葡月 1 日；1794-07-27 = 热月政变 |
| chinese | 2023 闰二月、2025 闰六月、春节日期、多日期对拍 |
| cli | 各子命令正常解析且退出码为 0 |

共 32 个用例，`python -m pytest -q` 全绿。

## 9. 可扩展性

新增一种历法只需三步：

1. 新建 `kaleidocal/new_calendar.py`，实现 `to_jd(...)` 与 `from_jd(...)`（或等价的两个方向函数）；
2. 在 `cli.py` 中加一个子命令；
3. 在 `tests/` 中加锚点对拍。

综合排盘会自动通过儒略日接入新历法，无需改动其他模块。
